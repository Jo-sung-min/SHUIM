## 요약

- **범위**: 로그인·세션, 커뮤니티 권한, 개인 기록 권한, 관리자, 결제, 업로드·미디어, AI, 3D 공간, 전송·인프라, 웹 보안, 개인정보·Play 정책, Android TWA, 의존성·빌드, 남용·확장성 — 14개 영역.
- **발견**: 후보 178건 (치명 7 · 높음 47 · 보통 56 · 낮음 54 · 참고 14). 같은 문제를 여러 영역이 겹쳐 보고한 경우가 많아, 실제로는 60개 안팎의 문제 묶음입니다.
- **검증**: 처음에는 건마다 관점별 반박 검증을 했고(52건 완료), 속도를 위해 간소화해 **수정 묶음이 고치기 전에 코드에서 직접 확인**하고 아니면 건너뛰게 했습니다. 마지막에 앱을 실제로 띄워 화면과 API 를 확인했고, 이 과정에서 테스트로는 안 잡히던 기동 실패 3건을 찾아 고쳤습니다.
- **처리 집계** (178건): 수정 100 · 일부 수정 39 · 운영자 조치 17 · 미룸 22. 치명 7건은 6건 수정, 1건(assetlinks 지문)은 운영자 조치. 심각도별 표는 [부록](#부록-전체-발견-목록).
- **결론**: 코드로 고칠 수 있는 출시 차단 항목은 고쳤습니다. 남은 차단 항목은 운영자 작업입니다 — ① 백엔드 HTTPS, ② assetlinks 지문, ③ 개인정보처리방침 운영 정보(LEGAL_*), ④ Play Console 선언, ⑤ OpenAI 사용 한도.

## 영역별 수정 내역

### 요청 제한·기본값 (백엔드 공통)
- `/api/**` 앞단 필터 3개: 출처 비밀 헤더(선택) → 속도 제한 → 본문 크기.
- 속도 제한: IP(X-Forwarded-For 첫 값)와 세션(쿠키·Bearer 해시) 두 키. 일반 한도는 통신사 NAT·3D 공간 tick 을 막지 않게 넉넉히(IP 분당 6000, 세션 분당 1200), 로그인·AI·메일 인증·쪽지·신고·업로드·결제·배너 클릭은 따로 좁게. 쿠키 없는 쓰기는 IP 당 시간 20번.
- 가짜 세션 쿠키로 위 한도를 비켜 가는 길을 막으려고, 익명 계정을 실제로 만드는 곳에 IP 당 시간 30개·전체 시간 3000개 한도를 한 번 더 둠.
- 본문 2MB 상한(관리자 사이트 설정·기록 동기화는 8MB). 잘못된 입력은 500 대신 400/413/415.
- 기본값을 운영 안전값으로: 샘플 계정 가짜 답글 끔(`COMMUNITY_SIMULATE=false`), 세션 쿠키 Secure 켬. 원격 DB 인데 출처가 localhost 이거나 Secure 가 꺼져 있으면 기동 때 경고.
- `/api/db` 는 `{configured, ok, latencyMs}` 만, 10초 캐시. `/api/site` 설정 60초 캐시. 원격 DB 연결에 `sslmode=require`.
- 모든 한도는 환경 변수로 조정, `RATE_LIMIT_ENABLED=false` 로 통째로 끔. 카운터는 메모리에 있어 **백엔드 인스턴스 하나**를 전제로 합니다.

### 로그인·계정
- 이메일 길이 254자 제한 후 선형 검사, 비밀번호 128자 상한.
- 비밀번호 해시(scrypt)를 DB 트랜잭션 밖에서 계산, 동시 계산 수 제한. 없는 계정에도 가짜 해시를 계산해 응답 시간으로 가입 여부가 드러나지 않게 함.
- 로그인 실패 문구 통일("이메일 또는 비밀번호가 맞지 않아요…"), 이메일별 15분 10회 실패 시 잠시 막음.
- 가입·로그인 때마다 세션 토큰 새로 발급(세션 고정 방지).
- 소로우를 만든 회원도 탈퇴할 수 있게 고침 (탈퇴 실패 버그).
- 카카오 가입 시 카카오 닉네임(대개 실명)을 공개 닉네임으로 쓰지 않음.
- 닉네임 규칙: 보이지 않는 문자·방향 바꾸기 문자·운영진 사칭어 금지 (가입·닉네임 변경·프로필 편집 모두).
- `KAKAO_ADMIN_KEY` 가 있으면 탈퇴 때 카카오 연결 끊기. 만료 세션 1시간마다 정리.
- `GET /api/auth/kakao?next=/account-deletion` 처럼 돌아갈 곳 지원(같은 사이트 상대 경로만).

### AI
- 위 표의 프롬프트·모델 덮어쓰기 차단, 하루 한도(오늘 브리핑 30회·익명 12회, 흐름 정리 20회·익명 8회, 전체 5000회), OpenAI 동시 호출 4개, 시간 초과.
- 입력 항목별 글자 수·카테고리 수 상한, 최종 프롬프트 길이 상한.
- OpenAI 에 사용자별 익명 식별자(`safety_identifier`, HMAC) 전달.
- 위기 표현 감지 범위를 넓히고, 규칙 기반 응답에도 자살예방상담전화 109·정신건강위기상담 1577-0199 안내.
- AI 응답·사용자 글을 오류 로그에 남기지 않음.

### 커뮤니티·쪽지·신고
- `GET /api/community`: 세션이 없으면 DB 에 아무것도 만들지 않는 손님(`me.id = "guest"`)으로 응답(Set-Cookie 없음). 읽기는 전역 잠금 없이 읽기 전용 트랜잭션에서 보는 사람과 무관한 스냅샷을 만들어 2초 캐시하고, 보는 사람 몫만 얹음. 동시 요청은 한 번만 DB 를 읽고, 쓰기가 커밋되면 캐시를 버림. 사람 찾기 O(N×U) → 색인.
- 공개 응답의 회원 명부 축소: 응답에 나오는 사람만, 닉네임·칭호·가입 여부만. 역할·정지 시각·정지 사유와 남의 힘내요·리스너 id 는 내려가지 않음(개수는 그대로). 관리자 응답은 전과 같음.
- 쿠키 없는 `GET /api/messages`(빈 목록)·`GET /api/profile`(401)·배지 확인이 익명 계정을 만들지 않음.
- 쪽지는 가입 회원만. 계정별 하루 한도(가입/익명): 글 30/10, 댓글 200/50, 피드 20/5, 신고 100/20, 쪽지 300. 넘으면 429.
- 익명 계정·가입 24시간 안 계정의 신고는 자동 가림에 세지 않음(관리자에게는 보임).
- 관리자 신고함은 첫 신고부터 보임. 쪽지 `?after` 조회 최대 200개.
- 안전 신고에 `circle`(소로우)·`space`(방명록·풍등) 종류 추가, 방명록 신고는 작성자 정지까지. 관리자가 자기 자신·다른 관리자를 정지하지 못하게 함.
- 글 삭제 때 S3 삭제를 전역 잠금 안에서 기다리지 않고 삭제 작업 대기열로. 피드 사진·릴스 표지도 우리 CDN·사이트 상대 경로만 받음.
- 알림 조회 15초 캐시(읽음·차단은 매번 반영).

### 소로우(모임)
- "다듬어 보기"·소로우지기 "AI 정리본"에 요청자 AI 동의 필요, 다른 사람 사연은 보낸 사람의 AI 동의도 필요.
- 사연 1200자 상한 후 마스킹, 이메일·전화 마스킹 정규식 선형화, AI 호출을 DB 트랜잭션 밖으로.
- 소로우 개설은 가입한 계정만, 정지된 계정은 지기 권한 없음, 신고가 들어온 글을 지기가 되살릴 수 없음.
- 멤버 전용 소로우를 글이 있는 상태로 공개 전환 막음. 메일 인증 코드를 응답에 싣지 않음(개발용 설정으로만).
- 쿠키 없는 조회가 익명 계정을 만들지 않음.

### 개인 기록·업로드
- 모루 마음기록 메모 id 선점으로 남의 일기를 가로채던 문제: 소유자가 다르면 저장하지 않음.
- 기록 동기화 상한(하루 카테고리 15칸, 요청당 20000칸, 날짜 2020-01-01 ~ 내일), 한 줄씩 INSERT → 묶음 INSERT.
- 업로드 발급 하루 한도(사진 150·영상 20, 익명 30·5, DB 기준), 크기 제한이 서명에 들어가는지 회귀 테스트, 어디에도 안 붙은 업로드 매시간 정리.
- 프로필 사진은 우리 CDN·사이트 상대 경로만 (외부 추적 이미지 차단). 바꾼 옛 사진은 삭제 대기열로.

### 3D 공간·결제·후원
- 대나무숲 방명록·우유니 풍등 소원: 커뮤니티 동의 확인, 금칙어·보이지 않는 문자 검사, 작성자 삭제(`DELETE /api/beach/guestbook/{id}`, `POST /api/beach/moments/remove`), 관리자 삭제(`DELETE /api/admin/beach/guestbook/{id}`, `DELETE /api/admin/beach/lanterns/{eventId}`), 정지된 작성자 글 숨김.
- 한 계정이 한 방(소로우×지도)에서 차지할 수 있는 자리는 2개 (탭 둘까지). 셋째로 들어오면 가장 오래된 방문을 내보냄.
- 방문 중에도 60초마다 세션·정지·강퇴·차단을 다시 확인해 바로 반영.
- 폭죽 이용권 요청 id 재사용 차단: 다른 방·다른 사람·재시작 뒤 다시 보내면 409 (영구 원장 기준, 마이그레이션 없음).
- 후원 기업 멋져요(이용권 받기): 회원 불꽃놀이가 닫혀 있으면 받지 않음(지금 운영은 닫혀 있음 → 화면도 "곧 열려요"), 가입 24시간 미만 불가, 30일 30회 상한.
- 배너 클릭은 세션·IP·날짜마다 한 번만 셈.
- 빈 방 정리, 공용 공간의 감정구슬에 낯선 사람 id·닉네임을 남기지 않음.

### 웹 보안·플랫폼 (프런트)
- 보안 헤더: nosniff, X-Frame-Options DENY, Referrer-Policy, Permissions-Policy(카메라·마이크·위치 등 끔), CSP `frame-ancestors 'none'; base-uri 'self'; object-src 'none'`, X-Powered-By 제거.
- JSON-LD 의 `<`·`>`·`&` 이스케이프 (관리자 사이트 제목으로 전 페이지 스크립트 주입 차단).
- `proxy.ts`: `ORIGIN_SHARED_SECRET` 이 있으면 백엔드로 가는 요청에 비밀 헤더를 붙이고, 브라우저가 보낸 같은 헤더는 지움.
- `AbortSignal.any` 폴리필(오래된 Chrome 의 3D 공간 입장 실패), 외부 CSS 에 SRI, `/u/[id]` 검색 제외, 상태 확인 주기 30초 → 90초.
- 앱인토스 빌드 스크립트가 중간에 끊겨도 옮겨 둔 파일을 되돌리게 함.

### Android 사용성·개인정보 (프런트)
- 뒤로 가기: 열린 시트·사진 편집·글쓰기가 먼저 닫힘. 글쓰기 초안 보존.
- 로그아웃: 서버에 있는 기록의 기기 사본·AI 결과·이름/전화 사본을 지움. 이 기기에만 있는 작은 한 걸음·돌보기·모루 방은 남김. 못 보낸 기록이 있으면 지우지 않고 알림.
- 로그인할 때 이 기기의 게스트 기록을 계정으로 옮길지 물음 (기본: 옮기지 않음).
- 가입 동의 분리: [필수] 약관·처리방침, [필수] 만 14세 이상, [선택] AI 정보 처리·국외 이전(미국 OpenAI).

- 앱(TWA) 안에서는 디지털 상품 결제 화면을 숨김 (지금 판매는 꺼져 있음).

## 배포 호환 (프런트가 먼저 나감)

**새 프런트 + 옛 백엔드 (푸시 직후 ~ JAR 업로드 전)**
- 동작함: 가입 동의 분리(옛 백엔드도 `aiAccepted=false` 저장), 카카오 로그인 후 돌아가기(브라우저 저장소로 처리), 보안 헤더, 뒤로 가기, 로그아웃 정리.
- 아직 안 됨: 소로우·3D 공간 글 신고 → 옛 백엔드가 "신고 종류를 확인해 주세요" 로 거절(화면에 그 문구가 보임).

**새 백엔드가 올라간 뒤 바뀌는 응답**
- 429(요청 많음·하루 한도), 413(본문 큼), 415, 잘못된 입력 400.
- 쿠키 없는 조회(`/api/community`·`/api/messages`·`/api/profile`·소로우 목록)는 익명 계정을 만들지 않음.
- 쪽지·소로우 개설은 가입한 계정만. AI 다듬기는 AI 동의 필요.
- 세션 쿠키 기본 Secure, 샘플 계정 가짜 답글 기본 꺼짐.

**새 백엔드에서 화면이 달라지는 곳**
- 후원 기업 멋져요: 운영처럼 회원 불꽃놀이가 닫혀 있으면 새 프런트는 버튼을 "곧 열려요"로 잠그고, 새 백엔드는 403 으로 거절합니다 (`FIREWORKS_MEMBERS_ENABLED=true` 로 열면 다시 동작).
- 쪽지·소로우 개설을 익명 상태에서 시도하면 "로그인한 뒤…" 안내가 나옵니다.

**DB 마이그레이션**
- `V53__safety_report_circle_space.sql` 한 개: `safety_reports.kind` 의 CHECK 제약을 `('user','message','ai','circle','space')` 로 바꾸고 `target_id` 를 VARCHAR(36) → VARCHAR(80) 으로 넓힙니다. 넓히기만 하므로 옛 백엔드 코드와 함께 써도 문제가 없습니다(되돌릴 때 이전 JAR 를 올려도 동작).
- main 의 마지막 마이그레이션이 V52 라 다음 번호 V53 을 썼습니다. 운영 Flyway 는 낮은 번호가 나중에 들어오면 서버가 뜨지 않으므로, 다른 작업 공간이 V53 을 먼저 main 에 넣으면 이쪽 번호를 올려야 합니다.

## 운영자가 할 일

배포 기획서의 "출시를 막는 일" 표와 같습니다. 이번 점검에서 확인한 사실:

- 운영 `/privacy` 에 "검토 중입니다…", "공개 전 확정 예정" 이 보입니다 → Vercel 에 `LEGAL_POLICY_APPROVED=true`, `LEGAL_EFFECTIVE_DATE`, `LEGAL_RETENTION_NOTICE`, `LEGAL_PROCESSORS_NOTICE`, (선택) `LEGAL_OPERATOR_NAME`·`LEGAL_SUPPORT_EMAIL`·`LEGAL_PRIVACY_OFFICER`. 처리방침의 TODO(안전성 확보조치·파기 절차)와 약관·아동 안전 페이지의 TODO(아동 안전 담당자)도 채웁니다.
- 처리 위탁·국외 이전 안내(`LEGAL_PROCESSORS_NOTICE`)에 들어갈 곳: Vercel(웹), AWS 서울(백엔드·S3)·CloudFront(CDN), Supabase(DB, 실제 지역 확인), OpenAI(미국, AI), 카카오(로그인), 메일 발송 업체. 각 업체의 지역·보관 기간은 계약·콘솔에서 확인해 적습니다.
- `https://www.sorow.co.kr/.well-known/assetlinks.json` 이 503 → Play 앱 서명 키 SHA-256 을 `ANDROID_SHA256_FINGERPRINTS` 에.
- OpenAI 대시보드에서 소로우 전용 키와 월 사용 한도.
- Supabase: 앱 전용 최소 권한 DB 역할, Data API 를 쓰지 않으면 끄기(또는 모든 테이블 RLS).
- S3: 장기 IAM 키 대신 EB 인스턴스 역할, 업로드 경로만 쓰는 정책.
- 방 음악 4곡의 공개 재생 권리 확인.
