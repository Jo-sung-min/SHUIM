# 회원 설정과 비공개 테스트 소로우

## 관리자 회원 설정

`/admin` → **회원 설정**에서 가입 계정을 최근 순으로 보고, 닉네임 검색과 페이지 이동을 할 수 있다. 익명 방문 계정과 로그인 방법이 없는 샘플 계정은 제외한다. 이메일 주소·비밀번호·로그인 식별 키는 내려보내지 않는다.

| 유형 | 저장 값 | 의미 |
| --- | --- | --- |
| 일반 회원 | `member` | 기본 회원 유형 |
| 파트너 | `partner` | 관리자가 지정한 파트너 |
| 소로우지기 | `keeper` | 향후 소로우 운영 기능을 확장하기 위한 회원 유형 |

회원 유형은 `users.role`의 관리자 권한 및 각 소로우의 소유자·지기 권한과 별개다. 유형 저장으로 관리자 권한이나 다른 소로우 관리 권한을 부여하지 않는다. 실제 회원의 유형을 일괄 변경하지 않는다.

새 가입 및 익명 계정의 가입 전환부터 `registered_at`을 기록한다. 과거 계정의 정확한 가입일은 복원할 수 없어 `NULL`을 유지하고 화면에 **계정 생성일**로 구분한다.

## 헤송민의 소로우

- 이름: **헤송민의 소로우**, 주소: `/c/haesongmin-private-test`.
- 참여할 실제 계정은 사용자 확인에 따라 **관리자 성민**과 **송이**다. 동명의 일반 회원 성민과 구분한다. 계정 식별자는 코드나 마이그레이션에 넣지 않는다.
- 생성 시 두 계정을 고정 명단과 활성 멤버로 함께 등록한다. 기존 대표 소로우는 유지한다.
- 지정된 두 계정에만 목록·상세·글·댓글·알림·공간이 보인다. 다른 관리자에게도 예외를 허용하지 않는다.
- 소로우 목록과 홈에서 최상단에 고정한다. 바닷가와 우유니는 각각 동시 입장 정원 **4명**이다. 일반 소로우는 기존 100명이다.
- 초대 코드, 메일 인증, 일반 가입, 멤버 추가·탈퇴·역할 변경, 공개 전환, 공개 대표 소로우 지정으로 명단을 우회할 수 없다. 소개와 공지는 기존 소유자 권한으로 수정할 수 있다.
- 비공개 활동을 공개 프로필·배지·소로우 순위에 노출하지 않는다. 비공개 글에는 샘플 자동 답글을 만들지 않는다.

## 적용 순서

V29는 비공개 명단·고정·정원 필드를, V30은 회원 유형·가입 시각을 추가한다. 두 마이그레이션 모두 실제 테스트 소로우나 특정 계정을 자동 등록하지 않는다.

**공유 DB를 사용하는 구버전 서버가 남아 있으면 비공개 소로우를 만들면 안 된다.** 구버전은 새 비공개 필드를 모르므로 목록에 방을 노출할 수 있다. 이를 방지하기 위해 `PRIVATE_TEST_CIRCLES_ENABLED`는 기본 `false`다. 관리자 화면은 생성 상태를 확인하고 비활성 상태를 안내하며, 서버도 직접 생성 요청을 거부한다.

1. 공유 DB에 접속하는 모든 서버에 새 백엔드를 반영한다. 운영 프런트엔드에도 새 UI를 반영한다.
2. 운영 공개 목록이 새 `privateTest` 필드를 반환하고, 구버전 인스턴스가 더 이상 요청을 처리하지 않는지 확인한다.
3. 확인된 환경에서만 `PRIVATE_TEST_CIRCLES_ENABLED=true`로 설정한다.
4. 관리자 성민으로 **회원 설정**에서 송이를 선택하고 **테스트 소로우 만들기**를 누른다. 동일 소유자와 동일 상대의 재요청은 기존 소로우를 반환하므로 중복 생성되지 않는다.
5. 두 계정의 접근과 일반 회원·다른 관리자의 비노출을 확인한다.

2026-11-05 확인: 운영 `https://www.sorow.co.kr/api/circles`의 27개 소로우 ID가 로컬과 일치했고, 운영 응답에 `privateTest` 필드가 없었다. 따라서 운영 반영 전 실제 소로우 생성은 보류한다. 생성 가능 상태 확인은 관리자 전용 `GET /api/circles/private-test/status`, 생성은 `POST /api/circles/private-test`의 `{ "peerId": "선택한 회원 ID" }`를 사용한다.

비공개 소로우를 생성한 이후에는 비공개 접근 제어가 없는 구버전으로 되돌리면 안 된다. `PRIVATE_TEST_CIRCLES_ENABLED=false`는 신규 생성만 막으며 기존 비공개 데이터 보호를 대신하지 않는다.

## 검증

실제 서비스와 분리한 임시 PostgreSQL에 V1–V30을 적용하여 가입 목록·유형 저장, 비공개 접근, 동시 생성 중복 방지, 명단 우회 차단을 검사했다. 정원 검사는 동시 입장 경쟁, 방별 4명 제한, 복귀, 일반 공간 100명 유지를 포함한다. 브라우저 검사는 모의 API를 사용하여 실제 회원 설정을 변경하지 않는다.

- 비공개 소로우·공간: 최종 46개 통과. 현재 세션·명단 재검증과 일반 공간의 추가 DB 조회 없음 포함.
- 콘텐츠 비공개 처리: 19개 통과. 결제 진입 권한 회귀 3개 통과.
- 관리자 회원: 서버 11개, 프런트 11개 통과. 기존 관리자 명언 12개 및 공간 선택 9개 통과.
- 모바일 390px·PC 1280px: 검색, 저장 실패 후 재시도, 생성 허용·차단 상태, 가로 넘침과 브라우저 오류 없음 확인.
- 웹 프로덕션 빌드, 앱인토스 정적 빌드(`--skip-ait`), 백엔드 `bootJar` 성공. 앱인토스 빌드가 이동한 소스 83개가 원래 내용으로 복원된 것도 확인.
- 로컬 서버를 새 버전으로 재시작하여 DB 연결, `/c/home`·`/admin` 응답 200, 미인증 회원 관리 403·생성 상태 401을 확인. 공개 목록은 기존 27개이고 비공개 항목은 0개다.

로컬에서는 V29·V30이 적용된 상태이며 생성 기능은 계속 꺼 두었다. 운영 배포와 실제 방 생성은 아직 진행하지 않았다. 임시 DB와 검사용 파일은 정리했다.
