# 소로우 배포 준비 검증 기록

2026-10-21 · 운영자 루체 · 이번 UI·서비스 연결 상태·정책 동의 변경은 로컬 검증 완료, 운영 서버와 Play Console에는 아직 배포하지 않음. 기존 운영 서비스의 배포 이력과 구분합니다.

## 준비된 결과

- Android 앱 프로젝트: `android/`, 앱 ID `kr.co.sorow.app`, API 36.
- 설치 가능한 테스트 파일: `android/dist/sorow-1.0.0-debug.apk`.
- release 빌드 확인용 파일: `android/dist/sorow-1.0.0-UNSIGNED-VALIDATION.aab`. **서명되지 않아 Play 제출 불가.** 운영 업로드 키로 새 AAB를 만들어야 함.
- 도메인 연결 엔드포인트, 설치 매니페스트, 개인정보를 캐시하지 않는 오프라인 안내.
- `/info` 서비스 안내 허브와 개인정보·약관·계정 삭제 공개 페이지, `/info/ai` AI 안내·동의·철회 화면.
- 가입 시 필수 정책 확인과 미체크 선택 AI 동의, 정책 버전 `2026-10-21`의 서버 저장, V13 `user_policy_consents` 마이그레이션. 같은 버전의 동의가 유효하면 AI 요청마다 브라우저 확인창을 반복하지 않으며, 서버도 미동의 요청을 거부.
- 계정 삭제, 사용자 차단, 안전 신고/관리자 검토, 별도의 커뮤니티 동의.
- 홈·내 공간·계정 및 공통 앱 UI 정리, 버튼 처리 중·중복 요청 방지. 백엔드가 응답하지 않으면 기본 콘텐츠 없이 준비 중 안내만 표시하고 공개 정책 페이지는 열 수 있도록 분리.
- 공개 관리자 우회 제거, 삭제 계정 확인, 계정 전환 캐시 분리, 기록 전송 실패 시 무한 재시도 수정.
- 스토어 설명, 데이터 보안 작성 근거, 실기기 시험 순서 및 조직 계정 가입 안내.
- 스토어용 512×512 아이콘과 1024×500 소개 이미지: [이미지 파일과 원본](assets/README.md). 실제 휴대전화 스크린샷은 최종 Play 설치본에서 별도 촬영해야 함.

서버 검사는 폐기 가능한 로컬 PostgreSQL을 사용했으며 운영 DB를 사용하지 않았습니다. 이번 검증으로 Play 설치본이나 운영 AI/S3/카카오를 포함한 전체 실기기 시험을 완료한 것은 아닙니다.

## 사진 첨부 개선 검증

- 기기 사진 여러 장 선택(최대 10장) → 미리보기 → 자르기/회전/확대 → 순서 변경 → 내용 작성 → 게시. 기본 그림 목록과 사진 주소 입력은 제거.
- 프로필은 정사각형 편집 후 저장, 관리자 서비스 이미지는 선택 후 미리보기·저장으로 변경.
- 로컬 모바일 브라우저에서 사진 2장 선택·순서 변경·실제 crop JPEG 생성(507×507)·사진 넘김·프로필 사진 저장 확인.
- 전송 실패 및 전송 성공 후 게시 실패를 각각 주입하여 사진/글 유지 확인. 마지막 게시 재시도에서는 사진을 다시 전송하지 않고 성공. 정상적인 클릭 중복은 화면에서 차단하고, 응답 유실 재시도는 V14의 작성자별 요청 UUID로 중복 저장 방지.
- 전송은 로컬 테스트 전용 모의 저장소를 사용하고 게시/프로필은 실제 로컬 백엔드·PostgreSQL을 사용. 운영 사진 저장소 검증과 실물 Android 촬영·핀치 검증을 대체하지 않음.
- 운영 공개 상태 `https://www.sorow.co.kr/api/upload/presign` 확인 결과 `configured:false`. 새 화면/JAR 배포와 운영 사진 저장소 연결 후 실제 사진 게시·삭제 재시험 필요.
- 새 배포 JAR: `backend/build/libs/sorow-server-2026-10-21.jar`, 48,286,775 bytes. SHA-256: `AE6CF423F9850F99D1378CF65EC275C39F71AF8D1F33B3A3DD33A533673F385F`.
- 사진 관련 자동 검사는 `npm run test:media`로 다시 실행할 수 있음.

## 이전 Android 준비 단계의 검증 기록

아래는 같은 날짜의 앞선 Android 준비 작업에서 얻은 결과를 보존한 것입니다. 이번 UI·동의 변경을 반영한 새 앱의 실기기 검증 결과가 아닙니다.

| 범위 | 당시 결과 |
| --- | --- |
| Android debug APK + lint | 성공 |
| Android release AAB + lint | 서명 없이 구성 검증 성공. 운영 서명 필수 보호 동작 별도 확인 |
| Android 16 에뮬레이터 | 설치·첫 실행·당시 운영 홈 표시 성공. 도메인 검증 전 주소창이 있는 화면 |
| 공개 정책 화면·웹 설치 자원 | 당시 로컬 브라우저/HTTP 점검에서 개인정보·계정 삭제·지원 이메일, 매니페스트·아이콘·오프라인 페이지·서비스워커 확인 |

Android 상세 검사와 당시 파일 해시는 [Android 검증 기록](../../android/VALIDATION.md)에 있습니다. 기존 APK/AAB 파일에 대한 기록이며 최신 UI 화면은 웹 배포 후 다시 확인해야 합니다.

다시 검증하려면 프런트엔드에서 `npm ci`, `npm run typecheck`, `npm run test:offline`, `npm run test:records`, `npm run test:privacy`, `npm run test:availability`, `npm run build`를 실행합니다. 백엔드는 `gradlew.bat test`입니다. PostgreSQL 통합 검사는 기본적으로 건너뛰며, 별도로 준비한 폐기 가능한 로컬 `sorow_test` DB와 동명의 사용자에 한해 `SOROW_TEST_DATABASE_URL=jdbc:postgresql://127.0.0.1:<테스트포트>/sorow_test`로 활성화합니다. 운영 `DB_URL`은 사용하지 않습니다.

## 의도적으로 아직 통과하지 않는 출시 점검

`frontend`에서 `npm run check:release -- https://sorow.co.kr`를 실행합니다. 현재 코드의 로컬 점검에서는 다음 사항을 미완료로 정확히 표시합니다.

1. **앱 서명 인증서 없음:** `/.well-known/assetlinks.json`이 503. Play 앱 서명 인증서를 `ANDROID_SHA256_FINGERPRINTS`에 설정해야 함.
2. **정책 안내 준비용 상태:** 보유기간·처리업체/국가·시행일을 확정하고 `LEGAL_*`를 설정한 뒤 승인해야 함. 단순히 배너만 없애고 제출하면 안 됨.

운영자 가입·서명·공개 웹 배포·최종 스크린샷·데이터 보안 선언·기기 시험·심사 제출은 [배포 안내](README.md)의 순서로 진행합니다. 준비 코드와 검증용 AAB가 있다는 사실은 Google Play 심사 통과나 즉시 제출 가능 상태를 의미하지 않습니다.
