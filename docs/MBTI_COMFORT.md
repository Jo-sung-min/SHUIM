# MBTI별 위로 방향 — 칭찬받기·사랑받기의 지침

작성 2026-11-12. 코드는 적용됐고 배포는 하지 않았다. 백엔드 JAR 를 올려야 켜진다 (아래 "배포").

## 무엇

사용자가 프로필에 MBTI 를 적어 두면(선택), 홈의 **칭찬받기·사랑받기**가 그 유형이 위로받고 싶어 하는 방향으로 말한다.
유형마다의 방향은 DB 표(`mbti_comfort_guides`)에 있고, 서버가 AI 에게 건네는 지침 끝에 덧붙인다.

| 조각 | 내용 | 어디 |
|---|---|---|
| MBTI 받기 | 프로필 편집 시트의 "MBTI (나만 보기 · 선택)". 자리마다 둘 중 하나(E·I / S·N / T·F / J·P)를 고르고, 네 자리를 모두 고르거나 모두 비워야 저장된다 | `frontend/components/ProfileSheet.tsx` |
| 저장 | `profiles.mbti` (4글자, 없으면 NULL). `PUT /api/profile` 의 `mbti` (`""` 이면 지움, 키가 없으면 그대로), `GET /api/profile` 응답의 `mbti` | `ProfileService.setMbti`, `ProfileController` |
| 유형별 방향 | 16행. 유형마다 `direction`(위로받고 싶어 하는 방향) · `praise`(닿는 칭찬) · `love`(닿는 사랑의 말) · `avoid`(피할 말) | `V51__mbti_comfort.sql` |
| 지침으로 적용 | `POST /api/today` 의 `praise`·`love` 에서, 요청을 보낸 계정의 MBTI 를 서버가 세션으로 직접 읽어 그 행을 시스템 프롬프트 끝에 붙인다 | `ai/MbtiComfortService`, `Prompts.comfort`, `TodayService.run` |

## 정한 것

- **참고 지침이다.** 지침은 "일반적인 경향이고, 오늘 기록에 드러난 마음이 언제나 먼저"라는 문장과 함께 건넨다. 문단 순서(위로 → 공감 → 칭찬 등), 근거 규칙, 조언·비교·진단 금지는 그대로다. 달라지는 것은 무엇을 먼저 알아주고 어떤 결로 말하느냐뿐이다.
- **유형을 입에 올리지 않는다.** AI 에게 MBTI 네 글자를 보내지 않고(방향 문구만 보낸다), 응답에 유형 이름이나 "너는 이런 사람이라서" 같은 말을 쓰지 못하게 했다.
- **위험 신호가 있는 날은 붙이지 않는다.** 기록에 자해·자살 표현이 있으면 109 안내 규칙이 먼저다.
- **칭찬받기·사랑받기에만.** 정리하기·분석하기·기간 요약에는 쓰지 않는다. AI 키가 없거나 실패해서 나오는 규칙 기반 응답("간단 버전")에도 쓰지 않는다.
- **관리자가 프롬프트를 덮어써도 붙는다.** 화자(모루)와 같은 방식으로 서버가 끝에 덧붙인다.
- **로그인 계정만.** MBTI 는 서버의 프로필에 있어서 비로그인 사용자에게는 적용되지 않는다.
- **본인용 항목이다.** 공개 프로필에는 나가지 않는다. `mbti` 만 보내는 저장은 커뮤니티 동의와 무관하다(지금 화면은 프로필 전체를 함께 저장해서 동의를 거친다).

## 표의 문구를 고칠 때

문구는 초안이다. 유형론에서 흔히 말하는 경향(T/F: 사실·인정 ↔ 공감, I/E: 조용히 ↔ 함께, S/N: 구체적인 일 ↔ 의미, J/P: 분명함 ↔ 느슨함)을 소로우의 말투로 옮긴 것이고, 조사나 사용자 반응으로 확인한 내용이 아니다. MBTI 자체가 사람을 정확히 나누는 도구는 아니라서 지침을 "참고"로만 쓰게 했다.

```sql
UPDATE mbti_comfort_guides SET praise = '…', updated_at = now() WHERE mbti = 'INFP';
```

- 서버는 표를 10분 동안 기억했다가 다시 읽는다. 고친 뒤 10분 안에 반영되고 다시 배포할 필요가 없다.
- 한 칸은 300자까지만 쓰인다(`Prompts.COMFORT_MAX`). 넘는 부분은 잘린다.
- 칭찬받기·사랑받기의 규칙과 부딪히는 말은 넣지 않는다: 조언·해결책, 남과의 비교, 진단.
- 관리 화면은 없다. SQL 로 고친다.

## 배포

1. 프런트는 `main` 푸시로 먼저 나가도 된다. 옛 서버의 응답에는 `mbti` 가 없어서 입력 칸이 보이지 않는다.
2. 백엔드 JAR 를 올리면 시작할 때 Flyway 가 V51 을 적용한다: `profiles.mbti` 열 추가, `mbti_comfort_guides` 표와 16행. 추가 전용이라 기존 데이터는 바뀌지 않는다.
3. 마이그레이션 번호: 2026-11-12 기준 `main` 과 모든 원격 브랜치의 마지막이 V50 이다. 올리기 전에 다른 브랜치가 V51 을 쓰지 않았는지 다시 확인한다.
4. 개인정보 처리방침(`/privacy`)의 "선택 프로필"에 MBTI 를, AI 이용 안내(`/info/ai`)의 "어떤 정보가 전달되나요?"에 말투 지침을 적어 넣었다. 처리방침의 시행일은 환경변수(`LEGAL_EFFECTIVE_DATE`)라 바꾸지 않았다. 문구와 시행일은 운영자가 확인한다.

## 확인한 것과 못 한 것

- 백엔드 단위 시험: `TodayComfortTest` 10개(칭찬·사랑에만 붙는지, 각자의 문구를 받는지, 위험 신호가 있는 날과 다른 모드에는 붙지 않는지, 지침이 없으면 프롬프트가 예전과 글자까지 같은지, 관리자 덮어쓰기 뒤에도 붙는지, 네 글자가 프롬프트에 없는지, 긴 문구가 잘리는지, V51 의 16유형이 한 번씩 있고 잘릴 만큼 긴 문구가 없는지), `MbtiTest` 1개. 기존 AI 시험도 그대로 통과.
- 프런트: 타입 검사 통과. 가짜 서버를 붙인 브라우저에서 프로필 시트의 고르기(두 자리만 고르면 저장이 막히고 안내가 뜸) → 저장(`mbti: "INFP"` 전송) → 다시 열면 그대로 → 지우기(`""` 전송)를 확인했다.
- **못 한 것:** V51 을 실제 PostgreSQL 에 적용해 보지 않았다(로컬 백엔드의 `.env` 가 운영 DB 를 가리켜서 띄우지 않았다). `ProfileService`·`MbtiComfortService` 의 SQL 과 세션에서 MBTI 를 읽는 경로도 실제 DB 로는 돌려 보지 않았다. 지침이 붙은 실제 AI 응답이 어떻게 달라지는지도 보지 않았다. MBTI 칸의 모양은 화면으로 보지 못했다(동작만 확인).
