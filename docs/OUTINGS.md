# 우리의 바깥 — 모루와 함께하는 외출

메인화면의 모루 아래에서 `/outing`으로 들어간다. 공원·바다·산은 첫날부터 방문할 수 있고, `/outing/space?place=park|sea|mountain`에서 동행 캐릭터와 함께 쉰다.

## 경험

- 생성한 장소별 사진 3장을 사용하는 넓은 **2.5D 파노라마**. 드래그와 좌우 버튼으로 둘러보기, 확대·축소·중앙 복귀, 땅을 눌러 동행 이동, 캐릭터에게 말 걸기.
- 전경 안개·먼 안개·빛 입자·물결을 다른 속도로 움직여 깊이를 표현한다. 모바일에서 별도 WebGL 엔진이나 고용량 3D 모델을 내려받지 않는다.
- 공원: 나란히 앉기, 나뭇잎 줍기, 피크닉, 종이배, 반딧불, 100일 나무.
- 바다: 파도 듣기, 모래에 그리기, 조개 모으기, 편지, 별자리, 100일 약속.
- 산: 숨 고르기, 구름 보기, 차 나누기, 마음의 산울림, 해돋이, 별빛.
- 수집은 직접 3개를 고르고, 별은 5개를 잇는다. 모래에는 포인터로 직접 그리거나 키보드로 하트를 찍을 수 있다. 차·피크닉은 함께 나눌 것을 고른다. 편지는 선택 입력이며 개인 추억으로만 남는다.
- 풍경 소리는 사용자가 켰을 때만 Web Audio로 재생한다. 숨긴 탭에서는 멈추고 퇴장 시 자원을 닫는다. `prefers-reduced-motion`에서는 반복 움직임을 없앤다.

## 100일 성장

기존 밥·방 업그레이드와 별개인 **외출 레벨**을 사용한다. 연속 출석이 아닌, 첫 활동을 완료한 서로 다른 한국 날짜 100일을 센다. 첫 활동을 마치면 하루 호감도 10·경험치 20. 반복 활동에는 추가 성장 보상이 없다. 미방문·기분·기록의 내용으로 차감하지 않는다.

| 함께한 날 | 외출 레벨 | 호감도 / 경험치 | 열리는 콘텐츠 |
|---|---|---|---|
| 0 | 1 | 0 / 0 | 세 장소, 쉬기·잎 줍기·모래 그리기·숨 고르기 |
| 7 | 2 | 70 / 140 | 피크닉, 조개 모으기 |
| 14 | 3 | 140 / 280 | 종이배, 따뜻한 차 |
| 30 | 4 | 300 / 600 | 바다 편지, 산울림 |
| 50 | 5 | 500 / 1,000 | 반딧불, 해돋이 |
| 75 | 6 | 750 / 1,500 | 두 장소의 별빛 활동 |
| 100 | 7 | 1,000 / 2,000 | 우리의 나무, 100일의 약속 |

100일 이후도 활동과 추억은 계속 이용할 수 있다. 보상·해금은 서버가 판단하고, 클라이언트가 보낸 날짜·점수는 받지 않는다. 활동 시작 토큰 및 12~20초 서버 경과 시간을 검사한다. 행 잠금과 단일 트랜잭션으로 여러 탭·기기의 같은 날 중복 보상을 막는다. 응답 유실 시 같은 완료 토큰 재시도는 보상을 반복하지 않는다. 시작 토큰은 30분 뒤 만료된다.

## 저장과 API

- `GET /api/outings`: 현재 계정의 성장·오늘의 활동·최근 추억 30장.
- `POST /api/outings/start { actionId }`: 해금 확인 후 시작 토큰과 완료 가능 시각.
- `POST /api/outings/complete { token, note? }`: 활동 완료, 그날 첫 보상, 추억 저장을 한 트랜잭션으로 처리.
- `V54__companion_outings.sql`: `outing_progress`, `outing_memories`. 계정 삭제 시 외래 키로 함께 삭제한다. 활동별 하루 한 장만 만들고, 다시 쓴 비어 있지 않은 한 줄은 갱신한다.
- 이름과 모습은 기존 계정별 모루 동행 설정을 따른다. 회원 기록은 서버에 저장하며 localStorage로 대신 성공 처리하지 않는다.
- 비회원은 기본 풍경·활동을 체험할 수 있다. 로그인 전 체험에는 영구 보상을 주지 않으며 UI에서 알린다. 서버 오류도 명시적으로 보여 주며 완료 저장을 꾸며내지 않는다.

## 통합모임

`/outing/meet`는 기존 커뮤니티 약속 동의를 거친 뒤 `public` 공간의 6개 맵 인원을 조회한다. 빈 맵 우선, 모두 사용 중이면 정원이 남은 맵 중 인원이 가장 적은 곳으로 바로 연결한다. 전체 만석·조회 실패는 재시도와 모임 목록 진입을 제공한다. 진입 시 기존 서버가 정원을 다시 검사한다. 인원 조회와 입장 사이 다른 사람이 들어올 수 있어 빈 맵 독점을 보장하지는 않는다. 나갈 때 자동 연결 화면으로 돌아오는 루프를 막기 위해 귀환 경로는 `/outing`이다.

## 에셋과 실행

공원·바다·산 배경은 이번 기능을 위해 생성했으며 `frontend/public/outing/*.webp`에 포함된다. 새 CDN 업로드가 없어도 제공되도록 이 경로는 기존 `assetUrl` CDN 변환 대상과 분리했다. 총 0.82 MiB 정도이고 외출 무대에서는 해당 장소 한 장을 사용한다.

백엔드를 배포/재시작할 때 Flyway V54 적용이 필요하다. 프론트엔드의 경로는 정적 페이지와 query parameter를 사용해 웹과 앱인토스 export 양쪽의 구조에 맞춘다. 이 작업은 원격 DB에 직접 접속해 마이그레이션을 수동 실행하거나 운영 배포하지 않는다.

검사: `npm run typecheck`, `npm run test:outing`, `npm run build`, 백엔드 `OutingRulesTest`와 `OutingControllerTest`.

## 검증 기록 — 2026-11-17

- 외출 전용 프론트 검사 7개 통과. 모임 맵·입장 생명주기·펫 클라이언트·모루 규칙을 포함한 78개 검사 통과.
- 백엔드 외출 규칙·인증 검사 8개 통과. Gradle은 이 환경에서 배포본 다운로드 및 daemon 연결을 완료하지 못해, 설치된 JDK와 캐시 의존성으로 컴파일 후 JUnit Platform으로 실행했다.
- Next.js 운영 번들 컴파일과 TypeScript 검사는 통과했다. 전체 빌드는 정적 페이지 생성 중 Windows `EPERM mkdir`로 완료하지 못했다. 기본 출력과 별도 출력/단일 worker에서도 기존 `/auth`, `/goals` 페이지의 segment 디렉터리 생성에서 같은 종류의 오류가 발생했다. 프로젝트 설정은 검사 전 값으로 유지했다.
- 별도 모임 연속성 검사 10개 중 기존 소파 복원 검사 1개가 실패했다 (`-14.15 ≈ -14.32`). 해당 검사와 의존하는 좌석/이동 엔진 파일은 이번 변경에서 수정하지 않았다.
- 실제 브라우저 상호작용, 원격 DB 마이그레이션 및 서버 통합 검증은 아직 수행하지 않았다. 서버 배포 시 V54 적용 후 로그인한 계정의 활동 완료·재접속·날짜 전환을 확인해야 한다.

## 검증 기록 — 2026-11-18 (커밋·배포 전)

- 실제 Postgres(버리는 로컬 DB, V54 까지 적용)로 외출 저장 흐름을 확인하는 시험 `OutingPostgresTest` 2개를 더했다: 시작 토큰, 너무 이른 완료 거절, 하루 한 번의 보상, 끊긴 응답 재시도, 같은 날 두 번째 활동, 빈 메모가 쓴 메모를 지우지 않는 것, 날짜가 바뀐 뒤의 보상, 계정 분리, 동행의 이름·모습, 계정 삭제 시 함께 지워지는 것. `SOROW_TEST_DATABASE_URL` 이 있을 때만 돈다.
- 백엔드 전체 시험 780개 통과 (앱 기동 시험 포함: V54 까지 적용한 DB 로 뜬다). 프런트 타입 검사와 외출 시험 7개 통과.
- 버리는 DB 에 붙인 로컬 서버에서 비회원으로 홈의 외출 칸, `/outing`, `/outing/space?place=park` 가 열리고 풍경 그림이 뜨는 것을 봤다 (콘솔 오류 없음). 회원으로 활동을 끝까지 해 보는 것과 운영 DB 의 V54 적용은 백엔드 JAR 를 올린 뒤에 확인해야 한다.
- 옛 서버(외출 API 없음)에서는 회원에게 "외출 준비가 아직 끝나지 않았어요"가 보이고, 비회원 둘러보기는 그대로 된다.
