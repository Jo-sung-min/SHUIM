# 100명 공간의 이동과 모바일 복귀

## 우선순위

1. **사용자의 미감**: 캐릭터 외형·모션, 하늘·은하수·물 반사, 조명과 공간 장식을 유지한다.
2. **공간 체험**: 다른 사람의 이동이 자연스럽게 이어지고, 카카오톡 등 다른 앱을 다녀와도 머물던 장소와 시점을 이어간다. 다른 방문자를 임의로 숨기거나 단순 이미지로 바꾸지 않는다.
3. **최적화**: 위의 두 조건을 지키면서 중복 계산, 불필요한 화면 갱신, 겹치는 요청을 줄인다. 이번 변경은 해상도나 장면 품질을 낮추지 않는다.

바닷가와 우유니 모두 같은 정책을 사용한다. 맵별 활성 방문 정원은 기존처럼 100명이다.

## 이동이 끊겨 보이는 문제

- 도착한 최신 좌표를 매 프레임 추격하던 방식 대신, 서버 변경 시각을 담은 최대 8개 위치 기록 사이를 일정한 시간축으로 재생한다. 수신 간격과 지터에 따라 작은 재생 지연을 조절한다.
- 실제 위치가 그대로인 생존 확인 응답은 새 이동 구간을 만들지 않는다. 오래된 응답은 폐기한다. 몸을 돌릴 때는 가까운 회전 방향을 선택한다.
- 패킷이 늦으면 마지막 이동을 최대 180ms만 감속 예측한 뒤 멈춘다. 복구 오차는 짧게 연결하되, 눕기·앉기·큰 위치 변경은 확정된 자리에 즉시 맞춘다.
- 걷는 동안 약 250ms, 다른 사람이 움직일 때 약 350ms, 모두 조용할 때 약 1초 간격으로 동기화한다. 요청에 걸린 시간도 간격에 포함하고 동시 중복 요청은 만들지 않는다. 장애 시 최대 6초까지 재시도 간격을 늘린다.
- 자신의 이동은 로컬에서 즉시 반응한다. 보간 지연은 다른 사람의 이동에만 적용한다.

## 앱 전환과 자리 복귀

| 상황 | 동작 |
| --- | --- |
| 다른 앱으로 이동 | 입력·자동 이동과 렌더링을 멈추고 마지막 위치를 전송한다. 퇴장 처리하지 않는다. |
| 약 10초 안에 돌아옴 | 현재 로그인·소로우 멤버 자격을 다시 확인하고 같은 방문과 서버가 유지한 침대·벤치 자리를 이어간다. |
| 10초 이상 자리를 비움 | 활성 정원과 공용 휴식 자리를 비워 준다. 최대 30분간 최근 위치를 보관한다. |
| 그 뒤 30분 안에 돌아옴 | 정원이 남아 있고 권한이 유효하면 최근 위치로 입장한다. 공용 침대·벤치가 만료된 경우 눕거나 앉기 전의 안전한 위치에 선다. |
| 같은 탭 새로고침·페이지 재생성 | 탭에 저장된 방문 힌트로 재인증하고 서버 위치 및 같은 계정의 시점을 복원한다. |
| 화면의 나가기·다른 페이지 이동 | 명시적으로 방문과 탭의 복귀 기록을 정리한다. |
| 통신 복구 | 겹치는 요청 없이 연결을 이어 간다. 확인되지 않은 인사·포옹 등의 행동은 자동 재전송하지 않는다. |

복귀 시 이동 패드의 눌림과 키보드·카메라 드래그 상태를 해제한다. 멈춘 동안의 다른 사람 이동 기록은 다시 재생하지 않는다. 서버가 확정한 휴식 상태에 맞춰 시점을 복원하고, 만료된 침대 시점을 서 있는 화면에 잘못 적용하지 않는다.

## 데이터와 순서 보장

- 탭의 `sessionStorage`에는 맵·소로우별 방문 힌트, 계정 ID, 요청 순서와 시점만 보관한다. 저장소 접근이 제한되면 현재 페이지의 메모리로 복귀한다.
- 서버가 실제 위치를 보관하고 복귀 요청의 로그인, 계정, 소로우·지도, 현재 멤버 권한을 검증한다. 탭의 힌트만으로 공용 자리를 선점할 수 없다.
- 이동·숨김·재입장에 증가하는 순서 번호를 붙인다. 이전 요청이 늦게 도착해도 최신 이동이나 숨김 상태를 되돌리지 않는다. 이전 계정의 카메라와 캐릭터 선택도 새 계정으로 넘기지 않는다.
- 재입장의 오래된 순서는 닉네임·차단 목록·캐릭터 갱신 전에도 검사한다. 서버가 모르는 이전 토큰으로 새 방문을 만든 경우에는 30초 동안 같은 사용자·소로우·지도의 재시도를 그 방문에 연결한다. 첫 성공 응답이 유실돼도 두 자리를 차지하지 않으며, 이 임시 연결도 방별 500개 상한에 포함한다.
- 앱 숨김 때 진행 중인 위치 요청을 취소하고 해당 세대의 늦은 응답을 버린다. 개발 모드의 초기 재마운트도 아직 확보하지 않은 저장 방문을 퇴장시키지 않는다.
- 방별 복귀 기록은 최대 500개다. 기록은 서버 메모리에 있으므로 **서버 재시작 시 사라지며**, 방문이 매우 많으면 30분 전에 오래된 기록부터 제거될 수 있다. 만석이면 기존 정원을 초과하지 않고 안내한다.
- 새 DB 테이블이나 데이터 이전은 필요하지 않다. 실제 서비스에 적용하려면 프론트와 백엔드를 함께 반영해야 한다.

## 외형을 유지하는 최적화

- 같은 캐릭터 원본의 경계 계산과 보정된 걷기 모션을 한 번 준비해 재사용한다. 각각의 뼈대와 애니메이션 상태는 독립적으로 유지한다.
- 자세 계산에서 이미 수행되는 행렬 갱신을 다시 호출하지 않는다.
- 참가자 목록은 좌표·거리 순서만 바뀌면 다시 그리지 않는다. 이름·캐릭터·참여자가 바뀌면 갱신한다. 불 상태도 표시할 내용이 바뀌거나 시각 재동기화가 필요할 때 갱신한다.
- 화면 밖 사람을 제거하거나 새 품질 저하 정책을 추가하지 않는다. 장면의 기존 품질 설정을 유지한다.

## 검증 결과

실제 남녀 캐릭터와 온천 캐릭터 4종의 서기·걷기·앉기·눕기·인사·포옹을 기존 방식과 비교했다. 월드 행렬과 표본 스킨 정점의 오차는 1e-9 이하이며, 외형과 모션을 유지했다.

데스크톱 CPU에서 같은 100명 혼합 장면으로 비교한 결과:

| 항목 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| 캐릭터 100명 준비 | 453.5ms | 80.9ms |
| 준비 중 경계 계산용 정점 처리 | 1,503,600회 | 0회 |
| 걷기 모션 데이터 | 5,124,600 bytes | 204,984 bytes |
| 프레임당 전체 트리 순회 방문 | 20,400회 | 8,400회 |
| 자세 갱신 CPU 중앙값 | 5.04ms | 3.78ms |

250ms 위치 송신, 350ms 관찰, 25–120ms 지연 변동 시뮬레이션에서 연속 프레임의 이동 속도 편차 평균은 2.237m/s에서 0.176m/s로 줄었다. 실제 통신망 측정값은 아니다.

브라우저에서는 검사 API와 실제 CDN 자산·WebGL을 사용했다. 390×844, 터치·DPR 2 조건의 우유니에서 본인 포함 100명을 표시했고, 120프레임 중앙값 16.7ms·95백분위 16.8ms, 페이지 및 WebGL 오류 0을 확인했다. GPU는 GTX 1060이므로 이 값은 휴대전화 실기기 성능을 보장하지 않는다.

바닷가의 짧은 앱 전환은 동일 방문과 좌표 (7, 8)을 유지했다. 우유니의 방문 만료 후 복귀 및 새로고침은 좌표 (6, 7), 3인칭 시점, 바라보는 방향을 유지했다. 실제 모바일 카카오톡 전환은 기기별 후속 확인 대상이다. 숨김·복귀 이벤트와 네트워크는 브라우저에서 모사했다.

자동 검사는 순서 역전, 앱 숨김·복귀, 새로고침, 계정 변경, 오래된 응답, 명시적 퇴장, 입력 초기화, 100명 캐릭터 동등성, 공용 자리 만료와 복원, 사용자·소로우·지도 격리 및 동시 재입장을 포함한다. 실제 PostgreSQL 통합 검사는 이번 범위에 포함하지 않았다.

프론트 전체 325개 통과 후 마지막 초기 재마운트 회귀 1개를 추가했고, 해당 생명주기 파일의 9개 검사를 다시 통과했다(최종 등록 326종). 백엔드의 DB 없는 해변 검사 141개가 모두 통과했다. 웹 빌드, 앱인토스 빌드, 최종 TypeScript 검사도 통과했다. 웹 33개·앱인토스 41개 정적 페이지와 `sorow.ait` 2,135,367 bytes를 생성했다.

앱인토스 빌드에 필요한 API 주소는 실행 프로세스에만 지정했다. 빌드가 임시 변경하는 app 파일 82개, public 파일 17개, 루트 설정 11개의 사전·사후 해시가 일치하며 `.ait-stash`는 남지 않았다. 결과물을 업로드하거나 배포하지 않았다.
