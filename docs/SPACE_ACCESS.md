# 공용 공간과 소로우 공간

함께 쉬는 3D 공간(바닷가·우유니·대나무숲·봄물 정원·구름미그린 온천·바이칼)은 두 가지다.

| | 공용 공간 | 소로우 공간 |
| --- | --- | --- |
| 누가 들어오나 | 누구나: 가입하지 않고 둘러보는 방문자까지 (이용이 제한된 계정 제외, 함께 지킬 약속에 동의한 뒤) | 그 소로우의 승인된 멤버만 |
| 방 id (`communityId`) | `public` | 소로우 id |
| 열린 풍경 | 여섯 풍경 모두 | 멤버 수에 따라 하나씩 |
| 들어가는 곳 | 소로우 홈(`/c/home`) 맨 위 "만나서 위로하기" | 각 소로우 화면(`/c/{slug}`)의 "만나서 위로하기" |
| 정원 | 풍경마다 20명 | 풍경마다 20명 (비공개 테스트 소로우는 4명) |

두 공간은 서로 다른 방이다. 인원수·모닥불·방명록·불꽃놀이를 공유하지 않는다.

## 소로우 공간의 풍경이 열리는 순서

소로우를 열면 그 소로우만의 바닷가가 생긴다. 멤버가 풍경 하나의 정원(20명)을 넘을 때마다 다음 풍경이 하나씩 열린다.

| 활성 멤버 | 열리는 풍경 |
| ---: | --- |
| 1명부터 | 바닷가 |
| 21명부터 | 우유니 |
| 41명부터 | 대나무숲 |
| 61명부터 | 봄물 정원 |
| 81명부터 | 구름미그린 온천 |
| 101명부터 | 바이칼 |

- 정확히 20명일 때는 바닷가만이다 (사용자 확정: 21명부터 다음 풍경).
- 규칙은 서버 `kr.co.shuim.common.SpaceMaps` 한 곳에 있다 (`ORDER`, `MEMBERS_PER_MAP`). 새 풍경을 만들면 `ORDER` 에도 넣어야 하고, 빠지면 `BeachSpaceAccessTest` 가 실패한다.
- 승인 대기 중인 멤버와 리스닝은 세지 않는다.
- 참여자가 고정된 비공개 테스트 소로우는 늘 수 없으므로 모든 풍경이 열려 있다.
- **한 번 열린 풍경은 멤버가 줄어도 닫히지 않는다** (사용자 확정). 나가는 사람이 "내가 나가면 풍경이 닫힌다"는 부담을 지지 않게 하려는 것이다. 소로우마다 가장 많았던 활성 멤버 수를 `communities.space_member_peak` 에 남기고, 지금 멤버 수와 그 값 중 큰 쪽으로 판단한다. 가입·승인·메일 인증으로 멤버가 늘 때 올리고, 소로우 화면을 열 때도 한 번 더 맞춘다.
- 지금 있는 소로우도 같은 규칙을 따른다 (사용자 확정). V48 이 현재 멤버 수를 최고치로 넣어 두므로, 배포 시점의 멤버 수로 열린 풍경에서 시작한다.

## API

- `POST /api/beach/enter { communityId: "public" | 소로우 id, mapId }`
  - 응답의 `shared` 가 `true` 면 공용 공간이다. `community` 는 `{ id: "public", slug: "", name: "공용 공간" }`.
  - 공용 공간에 처음 들어올 때 커뮤니티 이용규칙 동의가 없으면 409.
  - 소로우 공간에서 아직 닫힌 풍경은 403 ("이 풍경은 소로우 멤버가 N명이 되면 열려요…"). `GET /api/beach/count` 도 같다.
- `GET /api/circles/mine` 응답에 `publicSpace: { id, name, capacity }` 가 붙는다. 화면은 이 값이 있을 때만 공용 풍경을 보여 주고, 없으면(옛 서버) 예전처럼 내 소로우의 공간을 보여 준다.
- `GET /api/circles/{slug}` 와 `mine` 의 내 소로우에 `spaceMaps: [{ id, open, members }]` 가 붙는다. `members` 는 그 풍경이 열리는 멤버 수다.

## 저장

- 방문·위로·인원수는 서버 메모리(`BeachService`)에 있고 방의 열쇠는 `(공간 id, 풍경)` 이다.
- 공용 공간의 모닥불(`beach_fires`, `beach_fire_wood_requests`)과 대나무숲 방명록(`bamboo_guestbook`)은 소로우 공간과 같은 테이블에 `community_id = 'public'` 으로 남는다. 공용 공간은 `communities` 에 행이 없어서 V48 이 이 세 테이블의 `communities` 외래 키를 풀었다.
- V48 은 `communities.space_member_peak`(가장 많았던 활성 멤버 수)도 추가한다.

## 배포 순서

프런트가 먼저 나가도 된다. 옛 서버는 `publicSpace` 와 `spaceMaps` 를 내려 주지 않으므로 화면은 예전과 똑같이 동작한다. 백엔드(JAR, V48 포함)가 올라가면 공용 공간과 풍경 잠금이 함께 켜진다.
