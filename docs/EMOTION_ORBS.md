# 감정구슬 보물찾기 · 맵 앨범

작성 2026-11-13. 맵에 머물다 우연히 발견하는 "감정구슬"과, 맵에서 찍은 사진을 모으는 "앨범". 둘 다 마이페이지의 보관함에서 본다.
수치는 모두 초기 조정안이다. **2026-11-13 적용했다** (맨 아래 "10. 적용"). 커밋·배포는 아직 하지 않았다.

## 결론 요약

- **무엇.** 소로우 맵에 오늘 10분 머물면 그 맵 어딘가에 구슬 하나가 조용히 생긴다. 안내하지 않는다. 걷다가 반짝이는 것을 보고 다가가 주우면, 그날의 기분을 닮은 색의 구슬이 보관함에 남는다. 하루에 하나.
- **왜.** 맵에 "머무는 것" 자체에 작은 우연을 얹는다. 구슬은 보상이 아니라 그날의 마음이 남긴 자국이다. 가라앉은 날의 구슬도 예쁘고, 귀함은 모두 같다.
- **구슬에 남는 것.** 날짜, 어느 맵의 어느 자리, 어느 공간(공용 공간·소로우 이름), 그날의 기분, 그 순간 같은 방에 있던 사람들의 닉네임.
- **앨범.** 맵에서 찍은 사진의 미리보기에 "앨범에 넣기"가 생긴다. 맵 이름·공간·찍은 때가 함께 남고, 마이페이지 보관함에서 다시 본다.
- **지킬 선.** 보관함과 앨범은 본인만 본다. 기분에 따라 구슬의 값이 달라지지 않는다. 못 찾은 날에 잃는 것이 없다. 화면에 "우울"이라는 낱말을 쓰지 않는다. 다른 작품의 그림·이름·설정을 가져오지 않는다 (9장).
- **드는 것.** 프런트 + 백엔드 + DB 마이그레이션 하나(V52). 백엔드 JAR 를 올리기 전에는 화면에 아무것도 보이지 않는다 (8장).

## 1. 다섯 구슬

기분 다섯 단계(`docs/MORU_MOOD_SYNC.md`)에 구슬이 하나씩 맞는다. 이름은 빛의 이름으로 짓고, 기분은 캐릭터가 쓰는 말 그대로 옆에 적는다.

| 단계 | 그날의 기분 | 구슬 이름 | 빛깔 | 안에 든 것 |
|---:|---|---|---|---|
| 1 | 울적해 | 깊은 물빛 구슬 | 짙은 남청 | 가라앉는 물방울 |
| 2 | 가라앉아 | 빗물빛 구슬 | 흐린 하늘빛 | 빗줄기 |
| 3 | 고요해 | 안개빛 구슬 | 은은한 진줏빛 | 엷은 안개 |
| 4 | 가벼워 | 새싹빛 구슬 | 연두 | 작은 새싹 |
| 5 | 행복해 | 햇살빛 구슬 | 살구·금빛 | 햇살 조각 |

- **귀함은 같다.** 드문 구슬·흔한 구슬이 없고, 구슬로 받는 포인트도 없다. 구슬을 얻으려고 기록을 꾸며 적을 이유를 만들지 않는다.
- **낮은 날의 구슬이 가장 공들인 빛이다.** 요청대로 가라앉은 날에는 "예쁜 푸른 구슬"이 남는다. 1단계는 깊은 바다색, 2단계는 비 오는 하늘색으로 나눈다.
- **모양.** 소로우의 손그림 결을 따른다: 살짝 찌그러진 유리알, 손으로 그은 듯한 윤곽선, 안에 작은 풍경 하나. 맵 안에서는 은은히 빛나는 작은 빛구슬로 떠 있다.

### 1.1 기분을 정하는 법

- 줍는 순간 화면이 `moodOf(기록, 오늘)`(`frontend/lib/moru-rules.ts`)로 계산한 단계가 구슬의 기분이다. 홈의 캐릭터가 그날 띠는 기분과 같다.
- **오늘 기록을 아직 안 썼으면** 캐릭터와 똑같이 여운(2~4단계)이나 고요를 따른다. 구슬 때문에 기록을 재촉하지 않는다.
- **오늘 기록에 위험 신호(`hasCrisisSignal`)가 있으면** 닮지 않고 안개빛(고요) 구슬이 남는다. 캐릭터가 그런 날 고요히 곁에 있는 것과 같다.
- **"마음 닮기"를 꺼 둔 기기에서는** 늘 안개빛 구슬이다.
- 서버는 단계가 1~5 인지만 확인한다. 구슬마다 값이 같아서 속일 이유가 없다. (서버가 같은 계산을 하는 것은 남은 것)
- 구슬의 기분은 주운 뒤 바뀌지 않는다. 같은 날 기록을 고쳐도 그대로다.
- 기분은 이 기기에 있는 기록에서 계산한다. 홈을 거치지 않고 맵으로 바로 들어온 기기는 오늘 기록을 아직 못 받았을 수 있어, 구슬이 생기는 순간에 기록을 한 번 받아 둔다.

## 2. 구슬이 생기는 규칙

| 무엇 | 정한 것 |
|---|---|
| 누가 | 가입한 회원. 익명 참여자와 이용이 제한된 계정에는 생기지 않는다 |
| 어디서 | 여섯 맵 모두(바닷가·우유니·대나무숲·봄물 정원·구름미그린 온천·바이칼), 공용 공간과 소로우 공간 모두 |
| 10분 | **오늘 맵에 머문 시간을 모두 합친다.** 맵을 옮겨도, 나갔다 다시 들어와도 이어진다. 화면이 보이고 연결돼 있을 때만 센다 (탭을 가리거나 앱을 내리면 멈춘다) |
| 누가 세나 | 서버. 맵 화면이 30초마다 "머무는 중"을 알리고, 서버가 한 번에 45초까지만 더한다. 90초 넘게 소식이 없던 구간은 세지 않는다 |
| 날짜 | 한국 날짜. 자정이 지나면 새 날이고 시간도 0부터 |
| 생기는 자리 | 지금 있는 맵에서 이름 붙은 자리 하나(3장)의 근처. 계정·날짜·맵으로 정해서 **그날 그 맵에서는 늘 같은 자리**다. 다른 맵으로 가면 그 맵의 자리에 있다 |
| 누구에게 보이나 | 나에게만. 사람마다 자기 구슬이 자기 자리에 있다 |
| 알림 | 없다. 소리도, 안내 문구도, 지도 표시도 없다. 멀리서도 보이는 은은한 빛뿐이다 |
| 줍기 | 가까이(2.6m) 가면 아래 행동 줄에 반짝이 그림과 "주워 보기" 버튼이 뜬다. 가까이에서 구슬을 직접 눌러도 된다. 앉거나 누워 있을 때는 뜨지 않는다 |
| 하루 한 개 | 서버가 (계정, 날짜)로 하나만 받는다. 이미 주운 날에는 구슬이 생기지 않는다 |
| 못 찾은 날 | 구슬은 자정에 사라진다. 잃는 것도, 아쉬워하는 문구도 없다 |

- 서버가 다시 뜨면 그날 모은 시간이 사라진다(방문도 함께 끊긴다). 드문 일이라 받아들인다.
- 지하 쉼터(우유니) 안에서는 구슬이 보이지 않는다. 구슬은 늘 지상의 걸어갈 수 있는 자리에 있다.
- 개발 확인용: `?orbAfter=초`(필요한 시간), `?orbSpot=자리 id`(자리 고정). 운영 빌드에서는 무시한다. 서버는 `app.orbs.stay-seconds` 로 따로 줄인다(기본 600).

### 2.1 발견과 줍기의 연출

1. 10분이 차면 구슬이 조용히 나타난다(1초쯤 서서히). 천천히 떠오르내리고, 둘레에 엷은 빛무리와 작은 반짝임이 돈다. 위로 가는 빛기둥이 엷게 서 있어 멀리서도 우연히 눈에 띈다. 색은 주울 때까지 정해지지 않은 흰빛이다.
2. 다가가면 빛기둥은 스러지고 빛무리는 시야를 가리지 않게 작아진다. 행동 줄에 버튼이 뜬다.
3. 주우면 구슬이 떠오르며 그날의 빛깔로 물들고, 카드가 뜬다: 구슬 그림, 이름, 장소와 함께 있던 사람들.
4. **처음 주운 날에만** 한 줄을 더한다: "맵에 머물다 보면 하루에 하나, 어딘가에 구슬이 생겨요." 그 전에는 어디에도 설명이 없다.

## 3. 구슬이 생기는 자리

맵마다 이름 붙은 자리를 여럿 두고, 그날의 자리 근처(자리에서 2.5~5m) 걸어갈 수 있는 곳에 놓는다. 화면이 맵의 충돌 규칙으로 "설 수 있는 곳"인지 확인하고, 안 되면 다음 자리로 넘어간다. 마지막에는 들어온 자리 근처에 둔다.
자리 목록은 `frontend/lib/beach/emotion-orb-spots.ts`.

| 우유니 (8) | 별빛 자리 · 새벽빛 호텔 앞 · 별물결 호텔 앞 · 별물결 호텔 뒤편 · 소금 평원 한가운데 · 서쪽 소금 평원 · 동쪽 소금 평원 · 소금 평원 끝 |
| 대나무숲 (14) | 둘레길 입구 · 첫걸음정 · 서쪽 대숲길 · 동쪽 대숲길 · 중턱 풀밭 · 바람정 · 솔숲정 · 윗 대숲길(둘) · 달빛정 · 정상 공터 · 하늘전망대 · 축제 게시판 · 비밀 정원 오솔길 |

- 물속과 모닥불 자리에는 두지 않는다 (구름 온천의 탕, 바닷가의 모닥불 둘레).

- 바이칼의 먼 자리(오로라 관측소 앞)는 걸어서 한참이다. 보물찾기의 재미로 두되, 너무 안 찾아지면 가까운 자리의 비중을 높인다 (정할 것 8).

## 4. 구슬에 남기는 것

| 무엇 | 어떻게 |
|---|---|
| 날짜 | 한국 날짜와 주운 시각 |
| 맵과 자리 | 맵 id, 자리 id, 그 순간의 자리 이름 (나중에 자리 이름이 바뀌어도 그대로) |
| 공간 | 공용 공간인지, 소로우라면 그 순간의 소로우 이름 |
| 기분 | 단계 1~5 |
| 함께 있던 사람들 | **서버가** 그 순간 같은 방에 있던 사람들을 읽어 닉네임을 그대로 적는다 (최대 20명). 계정도 함께 가리켜서 누르면 프로필로 간다 |

- 서로 차단한 사이는 방에서 애초에 보이지 않으므로 적히지 않는다. 나중에 차단한 사람은 보관함에서 가린다.
- 함께 있던 사람이 탈퇴하면 그 사람의 닉네임은 메모에서 지워지고 "지금은 떠난 친구 1명"으로만 남는다.
- 아무도 없었으면 "혼자 조용히 머문 날"이라고 적는다.
- 보관함은 **본인만** 본다. 기분은 비공개 기록에서 나온 것이라 공개 프로필에는 구슬이 없다.
- 구슬은 내려놓을 수 있다(보관함에서 지우기). 내려놓아도 그날 다시 얻을 수는 없다.

## 5. 마이페이지 보관함

- 나 페이지의 "나만 보여요" 줄 아래에 **보관함** 한 칸: 구슬 줄과 앨범 줄. "모두 보기"로 `/me/keepsakes` 에 간다.
- **구슬 줄은 첫 구슬을 주운 뒤에만 보인다.** 그 전에는 보관함에 앨범만 있다 (구슬의 존재를 미리 알리지 않는다).
- `/me/keepsakes`: 탭 둘(감정구슬 · 앨범). 구슬은 최근 것부터 격자로, 위에 가진 빛깔의 개수만 작게.
- 구슬을 누르면 시트: 큰 구슬, 이름, "그날의 기분 · 가라앉아", 날짜, "봄물 정원 · 버드나무 벤치 근처", 공간, 함께 있던 사람들, 내려놓기.
- 낮은 날의 구슬에도 권유나 판정 문구를 붙이지 않는다. 구슬은 그날을 그대로 담을 뿐이다.

## 6. 앨범

| 무엇 | 정한 것 |
|---|---|
| 넣기 | 맵의 사진 미리보기에 "앨범에 넣기". 누른 사진만 올라간다 (찍는다고 저절로 올라가지 않는다) |
| 올리는 법 | 기존 사진 첨부와 같은 길(서명된 PUT 으로 S3). 긴 변 1600px, WebP 로 줄여 올린다 |
| 함께 남는 것 | 맵, 공간 이름(공용 공간·소로우 이름), 넣은 때 |
| 한도 | 한 사람 100장 (`app.album.max`). 가득 차면 정리한 뒤 넣으라고 알린다. 한 장 5MB 이하(기존 한도) |
| 보기 | 보관함의 앨범 탭: 격자 → 누르면 크게, 맵·날짜, 저장·공유·지우기 |
| 지우기 | 목록에서 빼고, 사진 파일도 정리 작업(`object_deletion_jobs`)으로 지운다 |
| 누가 보나 | 본인만. 사진에는 다른 사람의 캐릭터·닉네임이 찍혀 있을 수 있어 공개하지 않는다 |
| 탈퇴 | 올린 사진은 기존 탈퇴 정리(`uploaded_objects`)에 포함돼 함께 지워진다 |

## 7. 서버

테이블 (V52, 추가 전용):

- `emotion_orbs`: 계정, 날짜(유일), 주운 때, 맵, 공간 id·이름, 자리 id·이름, 기분, 함께 있던 사람 수, 내려놓은 때.
- `emotion_orb_companions`: 구슬, 계정(탈퇴하면 함께 지워짐), 그때의 닉네임.
- `map_photos`: 계정, 사진 주소와 키, 맵, 공간 이름, 넣은 때.

API:

| 길 | 내용 |
|---|---|
| `GET /api/orbs` | 내 구슬 목록과 오늘 상태. 이 길이 없으면(옛 서버) 화면은 구슬을 모른다 |
| `POST /api/orbs/stay { ticket }` | 맵에 머무는 중. 방문 티켓이 내 것인지 확인하고 오늘 머문 시간을 더한다 → `{ day, stayMs, needMs, found }` |
| `POST /api/orbs/claim { ticket, mood, spotId, spotName }` | 줍기. 머문 시간(모자라면 425)과 하루 한 개(이미 주웠으면 409)를 확인하고, 맵·공간·함께 있던 사람을 서버가 방에서 읽어 저장한다 |
| `DELETE /api/orbs/{id}` | 내려놓기 (숨김. 그날의 자리는 그대로 차 있다) |
| `GET /api/album` | 내 사진 목록과 한도 |
| `POST /api/album { url, ticket?, mapId }` | 내가 올린 사진만 받는다. 티켓이 살아 있으면 맵·공간은 서버가 읽는다 |
| `DELETE /api/album/{id}` | 지우기 |

머문 시간은 서버 메모리에 둔다(방문과 같다). DB 에는 주운 구슬만 남는다.

## 8. 옛 서버를 만났을 때

이 프로젝트는 새 기능을 서버가 알려 줄 때만 보여 준다.

- `GET /api/orbs` 가 없으면: 맵에 구슬이 생기지 않고, 보관함에 구슬 줄이 없다.
- `GET /api/album` 이 없으면: 사진 미리보기에 "앨범에 넣기"가 없고, 보관함에 앨범 줄이 없다.
- 둘 다 없으면 나 페이지에 보관함 칸 자체가 없다. 프런트가 먼저 나가도 깨지는 화면이 없다.

## 9. 지킬 선

| 걱정 | 정한 것 |
|---|---|
| 다른 작품을 따라 하는 것 | "감정이 구슬로 남는다"는 발상만 빌린다. 그 영화의 캐릭터·이름·구슬의 생김새·선반·기억 저장소 같은 그림과 설정은 쓰지 않는다. 구슬은 소로우의 손그림 유리알이고, 이름은 빛의 이름이며, 담기는 것은 "그날 그 자리와 함께 있던 사람"이다 |
| 화면의 말 | 기존 결정대로 "울적해·가라앉아·고요해·가벼워·행복해"만 쓴다. "우울 구슬"이라고 부르지 않는다 (2026-11-13 확정) |
| 구슬을 얻으려고 기록을 꾸미는 것 | 구슬의 값은 모두 같다. 포인트·배지·도감 완성 보상이 없다. "다섯 빛깔을 다 모아 보세요" 같은 문구를 쓰지 않는다 |
| 가라앉은 사람에게 가라앉은 구슬을 쌓아 보여 주는 것 | 판정·통계 문구를 붙이지 않는다("이번 달 울적한 날 7일" 같은 것 없음). 빛깔별 개수는 작은 점으로만 보인다. 내려놓을 수 있다. 위험 신호가 있는 날은 고요 구슬이다 |
| 매일 들어오게 만드는 압박 | 연속 기록·놓친 날 표시가 없다. 못 찾은 날에 잃는 것이 없다 |
| 남에게 보이는 것 | 보관함·앨범은 본인만. 구슬은 맵에서도 나에게만 보인다. 함께 있던 사람의 이름은 내 보관함에만 남는다 |
| 함께 있던 사람의 동의 | 같은 방에서 서로 닉네임을 보던 사이의 닉네임만 적는다. 차단·탈퇴하면 지워진다 |

기획과 달라진 점:

- 버튼의 글자는 "주워 보기"다 (행동 줄의 칸이 좁다). 읽어 주는 이름은 "반짝이는 것 주워 보기".

확인한 것:

- 타입 검사 통과. 프런트 규칙 시험 14개 통과. 기존 맵 시험 728개 가운데 727개 통과 (남은 1개 `beach-continuity` 의 소파 자리 시험은 이 작업 전의 코드에서도 똑같이 실패한다). `scripts/upload.test.mjs` 는 이 작업과 무관하게 14개 모두 실패한다 (`photo-edit.ts` 의 import 를 시험이 읽지 못한다).
- 백엔드 전체 시험 672개 통과 (일회용 Postgres 로 통합 시험 포함, 건너뛴 것 없음).
- 가짜 API 를 붙인 360×760 브라우저에서: 필요한 시간을 20초로 줄여 봄물 정원에서 구슬이 생기는 것, 9m 밖에서 보이는 것, 다가가면 버튼이 뜨는 것, 줍기(빗물빛 구슬 · 장소 · 함께 있던 두 사람 · 처음 한 번의 설명), 주운 뒤 다시 생기지 않고 신호도 멈추는 것, 구슬을 직접 눌러 줍기, 기록에 따른 빛깔(가라앉아 → 빗물빛, 행복해 → 햇살빛, 위험 신호 → 안개빛), 혼자였던 날의 문구, 사진 → 동의 → 앨범에 넣기(WebP 로 올라감), 나 페이지의 보관함 칸, 보관함 화면의 두 탭, 구슬 시트와 내려놓기, 사진 시트와 지우기, 옛 서버일 때 구슬·앨범·보관함 칸이 모두 없는 것.
- 여섯 맵 모두에서 엔진의 충돌 규칙으로 자리 63곳을 돌려 봤다: 모든 자리에 구슬이 놓이고, 물속에 놓이지 않는다.

못 본 것:

- 진짜 백엔드와 화면을 이어서 본 것 (서버는 시험으로만 확인했다. 로컬 백엔드는 운영 DB 라 띄우지 않았다).
- 진짜 S3 로 올리기, 앨범 사진의 저장·공유 (CDN 이 다른 출처의 받기를 막으면 새 창으로 연다).
- 실제 10분, 탭을 가렸다 돌아왔을 때, 자정을 넘길 때 (서버 시험으로만 확인).
- 구슬 자리까지 실제로 걸어서 닿는지: 충돌 규칙으로 "설 수 있는 곳"인지만 확인했고, 맵마다 몇 곳만 눈으로 봤다.
- 앱인토스 미니앱 빌드, 넓은 화면, 화면 읽기 프로그램.
- 개발 확인용: `?orbAfter=초`, `?orbSpot=자리 id`, `?moruMood=1~5` (운영 빌드에서는 무시).
